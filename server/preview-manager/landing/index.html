How it works

From merge request to live URL

No pipelines to write, no servers to babysit. One webhook does it all.

step 1

Open a merge request

GitLab fires a webhook to Druploy. Drafts are skipped, branch patterns you exclude are skipped, and you can require CI to pass first.

step 2

A machine claims your preview

A pre-provisioned VM from the warm pool picks up the job: clone, compose up, import your base database, run your deploy script.

step 3

The MR gets its URL

Druploy comments the live link on the merge request — with SSL, behind your team's auth if you want. Cleanup happens on close, automatically.

Why Druploy

Real isolation, Drupal depth

Most preview tools squeeze environments onto shared runners. Druploy gives each preview a whole VM — and understands Drupal down to the settings file.

A whole VM per preview

No shared containers, no noisy neighbors, no resource quotas fighting each other. Each preview boots its own machine and dies with the MR. Wildcard SSL covers every URL automatically.

One-click admin login

Generate a one-time Drupal login link from the preview page — or run any drush command against any preview, from the UI or your terminal.

Deploys you can watch

Phase-by-phase checklist with timings, real terminal logs streamed live over WebSocket, and a cancel button that actually cancels.

Self-cleaning infrastructure

Idle previews are erased after a period you set. Someone opens the URL later? Wake-on-request boots it back. Pin the ones that must stay.

A CLI that knows where you are

It reads your git remote and branch, resolves the right preview, and gets out of the way. Move databases and files between local and preview in one command.

Command line

Your previews, from the terminal

  • Passwordless login — a device flow opens your browser once, and you're in.
  • Data both ways — push a sanitized base DB for all new previews, or pull a preview's database straight into your local ddev.
  • Big files welcome — multi-gigabyte database uploads stream directly to object storage.
  • Self-updating — binaries for Linux and macOS, amd64 and arm64.
